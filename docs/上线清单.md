# 上线清单（从「本机能跑」到「小程序商城里能搜到」）

> 一句话结论：**代码侧只差「换配置 + 接微信登录/支付 + 部署到 https 域名」，资质侧（主体、备案、商户号、类目）必须你本人去办。**
> 自检命令：`node scripts/preflight.mjs --env .env`（FAIL 项必须先清零）。

---

## 一、必须先办下来的东西（技术做不了）

| # | 事项 | 说明 | 大概周期 / 成本 |
| --- | --- | --- | --- |
| 1 | 企业主体小程序 | 个人主体不能卖课收款；需营业执照 | 1～2 天 |
| 2 | 小程序认证 | 300 元/年，认证后才能用微信支付、才能被搜索 | 1～3 天 |
| 3 | 类目选择 | 「教育 → 在线教育」或「体育 → 健身」，需上传资质；**K12 学科培训禁止**，成人兴趣/健身属可做范围 | 随提审 |
| 4 | 域名 + ICP 备案 | 国内服务器必须备案，否则小程序 request 域名配不上 | 7～20 个工作日 |
| 5 | 微信支付商户号 | 企业资质申请，绑定小程序 appid | 1～3 天 |
| 6 | APIv3 证书 + 密钥 | 商户平台下载 `apiclient_key.pem`、设置 APIv3 密钥、下载平台证书 | 当天 |
| 7 | 服务器 | 1 核 2G 起（本后端单进程 + SQLite，很轻），约 100 元/月起 | 当天 |

## 二、技术侧改造（仓库里已经准备好了，按顺序执行）

```bash
# 1) 生产配置
cp .env.production.example .env
#    改：JWT_SECRET（openssl rand -hex 32）、ADMIN_PASS、WX_APPID/WX_SECRET
#        PAY_PROVIDER=wxpay + 六个 WXPAY_*、AI_API_KEY

# 2) 微信支付证书放到 certs/（权限 600，勿提交仓库）
#    certs/apiclient_key.pem、certs/wechatpay_platform_cert.pem

# 3) 上线自检（FAIL 必须清零）
node scripts/preflight.mjs --env .env

# 4) 部署（二选一）
#    A. systemd：
sudo cp deploy/systemd/yoga.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now yoga
#    B. pm2：
pm2 start deploy/ecosystem.config.cjs --env production && pm2 save

# 5) Nginx + HTTPS
sudo cp deploy/nginx/yoga.conf /etc/nginx/conf.d/yoga.conf   # 改域名/证书路径
sudo certbot --nginx -d your-domain.com
sudo nginx -t && sudo systemctl reload nginx

# 6) 小程序端服务地址改成 https 域名
#    miniprogram/utils/config.js 的 DEFAULT_BASE_URL
```

改造完成后要满足：

- [ ] `NODE_ENV=production`、`ALLOW_DEV_LOGIN=false`（生产默认已关）
- [ ] `PAY_PROVIDER=wxpay`、`MOCK_AUTO_PAY=0`，支付回调 `https://域名/api/payment/wxpay/notify` 可被微信访问
- [ ] `WX_APPID` / `WX_SECRET` 是真实企业小程序（不是 `touristappid`）
- [ ] 小程序 `DEFAULT_BASE_URL` 是 https 域名
- [ ] 数据库文件与 `data/` 目录已纳入备份（SQLite 单文件，`sqlite3 .backup` 或直接拷贝 + WAL checkpoint）

## 三、小程序后台要配的

1. 开发管理 → 开发设置 → **服务器域名**：request 合法域名填 `https://your-domain.com`（支付回调同域）
2. 设置 → 基本设置 → **用户隐私保护指引**：勾选「收集用户信息（昵称、头像、手机号）」，与 `docs/隐私政策.md` 一致
3. 设置 → **服务类目**：教育/体育，上传资质
4. 版本管理 → 开发版本 → **提交审核**：填写功能页面路径（首页 / 课程详情 / 收银台 / 我的课程 / AI 商城 / 分销中心 / 客服）
5. 审核常要的补充：测试账号（把 `dev_demo_*` 换成审核专用账号，或在提审说明里给一个能走通下单+退款的路径）、经营资质截图、退款规则说明

## 四、三条需求各自的合规红线（务必逐条过）

### 1）卖课 + 退款
- **iOS 不能卖虚拟商品**：微信小程序在 iOS 端禁止虚拟商品支付（苹果规则）。课程 = 虚拟商品。
  现实做法：安卓/微信内正常支付；iOS 端只展示、引导线下报名或公众号 H5，绝不能在 iOS 内出现「支付」按钮 → 按平台差异化：`wx.getSystemInfoSync().platform === 'ios'` 时隐藏购买入口。

**代码现状（已实现）**：
  - 开关 `miniprogram/utils/config.js` → `IOS_PAY_DISABLED = true`；
  - 判定与提示 `miniprogram/utils/platform.js`（`isIOS()` / `payBlocked()` / `guardPay()`）；
  - 拦截点四处：`pages/detail/detail.js` 的 `onBuy`、`pages/confirm/confirm.js` 的 `onSubmit`、
    `pages/pay/pay.js` 的 `onLoad`、`pages/ai/ai.js` 的 `create_order|pay_order|mock_pay`；
  - iOS 上不出现购买按钮（详情页按钮文案改为「iOS 请联系客服报名」），仍可查课、看订单、退款、做分销。
  真机需在 iOS 设备上复核一次（本机无 iOS 设备/开发者工具）。
- **宣传文案别碰医疗功效**：若宣传"治疗颈椎病/产后康复"会被判超类目或违反《广告法》。
  **代码现状（已改）**：种子商品已改为「肩颈舒缓放松课」「孕产恢复期温和练习」，详情页补了「练习不能替代诊疗」
  「不构成医疗建议」的说明，目标标签「理疗」统一改为「舒缓」（`server/seed.js`、`server/modules/product/service.js`、
  `server/modules/ai/engine.js`）。存量库需重新 `npm run db:reset` 或手工更新商品表。
- **年卡会员属于预付式消费**：需明确有效期、退款规则、停业处理，页面要有《用户协议》入口。
- 退款政策要与微信支付「原路退回」一致，我们已实现（部分退款 + 7 天窗口 + 自动审核阈值）。

### 2）二级分销（风险最高的一条）
- 微信《小程序平台运营规范》明确禁止**多级分销/拉人头返利**；两级返佣有被判定违规下架的先例。
- 建议上线版本**只保留一级**：后台参数把 `commission_l2_bps` 设为 `0`（`scripts/preflight.mjs` 会 WARN 提醒）。
- 话术上避免"发展下线""团队计酬""层级返利"，改成"推荐奖励 / 推广员"；佣金只能来自**实际成交**，不能按人头计酬（我们已按订单金额比例，符合这一点）。
- 不要用"邀请码强制绑定不可更改"作为拉新手段宣传，容易被认定为诱导。

### 3）AI 商城
- AI 回复要能"说清是 AI"：页面已标「AI 课程顾问」，建议在欢迎语里写明"由 AI 提供，重要信息以页面为准"。
- 不能让 AI 承诺价格/优惠/退款结果：当前资金类动作走后端规则引擎（LLM 不能改），符合要求。
- 若接第三方大模型（`AI_PROVIDER=llm`），需在隐私政策里写明会把对话内容发送给第三方模型服务商。

## 五、上线后运维

| 事项 | 做法 |
| --- | --- |
| 备份 | 每日 `sqlite3 data/app.db ".backup 'backup/app-$(date +%F).db'"`，保留 14 天 |
| 日志 | systemd/pm2 已重定向到 `logs/`，用 `logrotate` 按周切 |
| 对账 | 每日对比 `payments` 表与微信支付账单，差异人工核 |
| 监控 | `/api/_health` 挂 uptime 监控；5xx 与退款率异常告警 |
| 灰度 | 先内部体验版跑 3～5 天（真实支付 1 分钱测试单），再全量 |
